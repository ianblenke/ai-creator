# CPU voice server (Kokoro-82M), compose profile `cpu`

A fallback for machines without an NVIDIA GPU. It speaks with Kokoro's preset voices; it CANNOT clone your voice.
It sounds clear but flat (an audiobook reader), so use it to learn the pipeline and to make drafts, not as your channel's voice.

    # .env.local: VOICE_TRANSPORT=http and VOICE_NAME=af_heart (and no VOICE_REF); with the default fixture, tts writes silence
    docker compose --profile cpu up -d voice-cpu      # first start downloads about 330 MB of weights into a named volume
    mkdir -p episodes && cp -r examples/ep01-kettle episodes/my-kettle   # never synthesize into the shipped example
    docker compose run --rm media tts episodes/my-kettle

This is also the lane for a topic made with `new` when you have no cloned voice yet: the fixture lane needs a committed
`timeline.json`, which a new topic does not have.

The service answers on the compose network as `voice`, so the default `VOICE_URL` (http://voice:8080) works unchanged.
Run only one voice profile at a time (`chatterbox`, `chatterbox-cpu`, `gpu`, `cpu`, `cpu-clone` and `stub` all claim the name `voice`).

Routes (the same as the GPU server):
- `POST /v1/audio/speech` with JSON `{"input": "...", "voice": "af_heart"}`: a 24 kHz mono WAV. `num_step` is accepted and ignored.
- `GET /v1/voices`: the English voice ids (`af_`/`am_` American, `bf_`/`bm_` British; f = female, m = male).
- `POST /v1/audio/speech/clone`: HTTP 501, because this fallback cannot clone.

Measured 2026-10-27 on a 16-core CPU with no GPU, one 5.5 s sentence (n = 1): 0.75 s, about 7 times faster than real time; image 2.2 GB;
about 2 GB RAM. Its output is quiet (about -25 LUFS); the tts stage normalizes it to -16 LUFS. WhisperX alignment of its output
matched every word of a 20 s scene.
