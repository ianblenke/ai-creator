## Plan first
Turning that idea into an episode is a chain of steps, and the first one happens before any audio exists. You decide what the episode says: one problem per episode, with every fact written down and sourced. That sounds slow, but it is the cheapest place to find a mistake. A wrong sentence costs nothing on paper. Once it is narrated and animated, fixing it costs a lot.

> VISUAL: A script page fills line by line, each fact line gets a small source tick. Beside it two bars grow on a flat axis with no numbers: a tiny bar for fixing a wrong sentence on paper, a tall bar for fixing it after it is narrated and animated. The tall bar is the one that glows magenta.

## The voice goes first
Once the script is solid, the voice comes next, because the narration sets the timing for everything else. Every picture is built to fit the audio, never the other way around. And because a voice model can slip in ways your ears miss, the pipeline checks the audio instead of trusting it.

> VISUAL: A long waveform sits as a ruler across the middle. Picture blocks below it snap to the waveform's timing, never the other way around; a small arrow shows the direction from audio to picture. Then a magnifier slides along the waveform and a magenta mark appears where a slip hides.

## Pictures as functions of time
With the narration fixed, the pictures can be built to fit it. A cloud model writes each animation as a small piece of code, and each frame is drawn from the time alone. So the same moment always draws the same frame, and you can render a frame twice and compare. That is how I caught a ghost: a leftover copy of a moving shape, one frame wide, that I never would have seen by eye.

> VISUAL: A clock reading 't' feeds a box that draws a frame. The same moment is fed in twice and two identical frames appear side by side. Then one frame shows a faint magenta leftover copy of a moving shape, one frame wide, found by laying the two frames over each other; the difference lights up magenta.

## The cast
Catching it took a machine, and that is how this whole setup works. Three different jobs, each done by a different model. One speaks, in my voice, on my own graphics card. One listens, and compares what it hears to the script. A cloud model writes the pictures, and a cloud agent runs the pipeline and checks the work, so that someone checks the checkers.

> VISUAL: Three flat jobs in a row, each with its own colour and a simple sign: a speaker (a waveform) running on a graphics card, a listener (an ear next to a script page and a small compare mark), and a cloud writer (a cloud with a code bracket). Above them a cloud agent runs the whole row, and a small loop arrow returns from the end to check the checkers.
