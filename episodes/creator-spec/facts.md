# One Problem per Episode: facts (sources are the repo's own docs and our own runs; every line dated)

## The plan page (docs/episode-plan-template.md, read 2026-11-03)
- `node tools/cli.js new <id>` creates episodes/<id>/ with plan.md, facts.md, script.md, must-hear.txt, youtube-description.md, scenes/_brief/_bible.md and thumbnail/thumb.html (our own run, 2026-11-03).
- plan.md is one page written before the script: Thesis (one sentence the viewer can repeat), Audience, Not covered, Facts needed, Scene sketch (5 to 10 lines, each with the bridge from the previous one), Risks (accuracy, disclosure, rights), Done when.
- The script critic reads plan.md to check the script against the thesis. The example series used a heavier spec tool (openspec); for one episode the one page is enough (the template's own words). Not covered here: openspec.
## The fact sheet (docs/fact-sheets.md, read 2026-11-03)
- facts.md is the only place the script and scenes may take a fact from. Every fact carries a marker: [cited] (a public source says it; link and read date), [measured] (you measured it; how, when, on what, n runs; say the date in the video), [estimated] (say what it is based on; the script says about or roughly).
- Method: write the claim, find a public source (prefer the primary one; a snippet, forum post or model answer is a lead, not a source), read the source itself, rewrite the claim no stronger than the source, record link and read date; if the source contradicts the thesis, change the plan; put what you will not say under "Not claimed".
- The sanitizing step: rewrite every device, room, place, person, host name, address, port, user name and file path in generic words; keep never-published material in a file the repository ignores; add every private name to safety/denylist.txt; run the safety command and fix every finding.
## The script (docs/script-format.md, read 2026-11-03)
- Each level-two heading starts a scene; narration paragraphs; lines starting `> VISUAL:` are notes for the scene author, never spoken or subtitled; `{{spoken: reed|read}}` overrides pronunciation; `{{pause: 0.9}}` on its own line is exact silence.
- Writing guidelines in that doc: every scene opens with a connective sentence; no stacked fact fragments, give each fact a clause on why the listener should care.
- `validate` fails on scenes without narration and on duplicate scene titles, and warns when the estimated length is outside the window (default 5 to 8 minutes; 160 words per minute plus 0.6 s per scene).
## The safety gate (docs/safety.md, read 2026-11-03; tools/safety/)
- Our own run, 2026-11-03: a freshly created episode, one invented line added to its script containing a made-up LAN-style machine name, a made-up address and a made-up port. I then ran the tts command on it: the gate blocked tts with those three findings, ipv4-address, private-domain and port-number, and no audio folder was created. Each finding had the file and line, a hint, and a MASKED sample (the first two characters then a count), so the report never repeats the secret. The invented line was removed afterwards; the repository was never committed with it.
- The gate runs before tts, scenes, keyframes, render, encode and the other gated steps, on demand with the safety command, and before every upload. It reads every file in the episode folder except audio and frames (tools/safety/scan.js episodeFiles), so a private-notes file kept inside the episode folder would be scanned and would block every gated step. This repository's .gitignore has no entry for a private-facts file: the author adds one (the setup in the doc does not do it). During keyframes it also scans the text the scenes actually draw.
- The denylist (safety/denylist.txt, gitignored): one name per line, matched as a whole word in any case. Until it is filled in, every gated command prints a banner of exclamation marks (MISSING, EMPTY or EXAMPLE); the gate still runs with its generic patterns.
- The interview categories: machines, accounts, people, places, projects, voice, and anything you would not print on a postcard. Do NOT list a name you show on purpose (your channel or series name): every episode would fail its own gate.
- repo-check, run by the pre-commit hook and by the safety command, blocks tracked or staged files by NAME: .env, .env.local, safety/denylist.txt, voice files other than a README and a consent example, .secrets/, generated folders, and every audio or video file extension anywhere in the repo. It cannot see audio renamed to another extension.
- The commit-msg hook removes lines that start with "Claude-Session:" and NOTHING else (it says so itself): other session links, attribution lines or pasted logs stay in; read your message.
- What it misses (docs/safety.md): names not on your denylist; a place or person described in words or shown; text inside pictures and video unless the OCR scan is run (needs tesseract, misreads small or stylised text); faces, reflections, window views, a terminal prompt or status line in a recording; audio, unless the name is in the script text; files outside the episode folder and history from before the hooks were on; commit messages beyond the one line.
- ocr-scan.js reads frames sampled every 0.5 s of every screen recording, screenshot and thumbnail by hand.
## Dated stamps
- Our own series practice: a number that can change gets "measured on <date>" said aloud and shown, so a later change does not make the video false (the template's own wording in the plan page and the fact-sheet doc).
## NOT claimed
- That the gate is complete. Real catches from any other project. openspec's commands. Any count of tests.
- The pre-commit and commit-msg hooks only work after `sh tools/hooks/install.sh`; `git commit --no-verify` skips both (git behaviour). repo-check checks file names only, never file contents (its own comment).
- validate checks structure only: scenes without narration and duplicate titles fail; a length outside the window is a warning; it does not check that scenes connect (tools/script.js, docs/script-format.md).
- The OCR scan needs tesseract; without it, it checks nothing (exit 2).
